# FluTrack Deferred Data Requests

The implemented interface uses only the existing state snapshot and live CDC read path. The following visual ideas were intentionally deferred because the current published model does not provide the stable, comparable data required to present them honestly.

| Request | Intended experience | Required data contract | Refresh and quality rules | Why deferred |
| --- | --- | --- | --- | --- |
| Eight-week composite history | A compact report chart beneath the instrument showing how the state’s **combined** 0–100 index changed across the last eight completed reporting weeks. | `compositeHistory`: eight or more ordered objects with `weekEnding`, `composite`, `level`, `trend`, and `provenance`; include `coverage` for each week. | Publish only completed weeks. Show a gap if source coverage drops below the current composite’s contributor threshold. Retain explicit latest-date and lag language. | The current client model emits raw component series but not a historical, versioned composite series calculated by the same formula. |
| Seasonal comparison band | A restrained range behind a state trend chart showing the historical seasonal range for the same reporting week. | `seasonalBaseline`: at least five completed seasons, with weekly median, interquartile range, sample count, and the current formula version. | Exclude incomplete or methodology-incompatible seasons. Recalculate all historical values whenever the formula changes. Label the comparison as historical context, not a forecast. | The current build contains one current snapshot and does not emit historical composite values, a formula version per history point, or a denominator for coverage. |
| State data-completeness ledger | An honest per-state line identifying which component sources contributed to the current composite and which were absent. | `contributors`: source key, latest observation date, availability, lag days, and any suppression reason for ED, wastewater, positivity, and ARI. | Keep no-data and partial-data reasons machine-readable. Do not infer absence from a zero value. | The model internally knows contributor keys but does not emit source-by-source dates, suppression reasons, or a stable availability state for presentation. |
| Regional comparison benchmark | A state’s current index positioned against a clearly defined peer group. | `regionalBenchmark`: explicit geography definition, member states, count, summary statistic, calculation week, and coverage rule. | State the peer geography in visible copy supplied by the owner. Recompute from the same data release as the subject state. | The current neighbor list is a simple HHS-region shortcut but does not establish a published peer methodology or a regional aggregate. |
| Data revision marker | A visible note when an upstream source revises a prior published week enough to change a state’s report. | `revision`: state, affected week, old and new component values, old and new composite, source timestamp, and revision reason where supplied. | Keep a revision record per state and week. Do not manufacture revisions when upstream feeds silently republish. | The current live refresh replaces state signals without persisting prior releases or a source-revision audit trail. |

These requests are specifications for a future data contract, not an instruction to change the present index, data fetching, routing, or reporting claims.
