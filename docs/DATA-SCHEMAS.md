# CDC data schemas

Columns were fetched from data.cdc.gov columns.json (`https://data.cdc.gov/api/views/<ID>/columns.json`) on 2026-10-09. Dataset names and cadence come from `https://data.cdc.gov/api/views/metadata/v1/<ID>`. Sample rows were fetched from SODA (`https://data.cdc.gov/resource/<ID>.json`) on the same day and are stored as fixtures in `test/fixtures/cdc/<ID>.json`.

The **fieldName** column is the API key you use in SoQL and in row objects. The **name** column is only the portal display label. In several datasets the two differ a lot, so never derive one from the other. Column examples come from `cachedContents.top` and the smallest/largest values in columns.json, unless a row says otherwise.

## Cross-cutting facts for the normalizer

- **All SODA values are strings**, including numbers (`"0.7"`, `"386.0"`, `"74.1900"`). Parse numbers explicitly.
- **Null fields are omitted** from row objects; they are not sent as `null`. Treat a missing key as null. For example, `numconfrsvnewadmped5to17pctchg` is absent from the CA 2026-09-26 row of `ua7e-t2fy`, and `inhibition_adjust` is absent from every `ymmh-divb` sample row.
- **Date formats differ by column type.** `calendar_date` columns return `"2026-09-26T00:00:00.000"`. Text date columns return `"2026-09-26"`. The same fieldName `weekendingdate` is `calendar_date` in `ua7e-t2fy`/`mpgq-jmmr` but `text` in `vdzy-6i9v`. `week_end` is `calendar_date` in `vutn-jzwm`/`f3zz-zga5` but `text` in `atcp-73re`.
- **Latest complete week across the weekly datasets is 2026-09-26** (Saturday), which is MMWR 2026 week 38 (Delphi epiweek `202638`). The preliminary HRD dataset `mpgq-jmmr` already has 2026-10-03 (week 39).
- **Aggregates:** `$select=source,count(*)&$group=source` returns the count under the key `count`.
- **State identifiers vary by dataset:** full names (`vutn-jzwm`, `f3zz-zga5`, `atcp-73re`), upper-case postal codes plus `USA` (`vdzy-6i9v`, `ua7e-t2fy`, `mpgq-jmmr`), and **lower-case** postal codes (`ymmh-divb`: `ca`).

**Notes for the normalizer**

- Geography: `state_territory` holds **full state names** (`"California"`), even though the description says "2-letter abbreviation". The sampling site is `site`, formatted `"ID:100"`. Population is `population_served`.
- County: there is **no FIPS column**. `counties_served` holds county **names** without a "County" suffix, as a comma-and-space list for multi-county sites (`"Los Angeles, Ventura"`, `"El Dorado, Nevada, Placer"`). 15 of 156 CA rows in the latest week are multi-county. The full dataset has 136 null `counties_served`. Getting FIPS needs a per-state name→FIPS lookup. Joining to `ymmh-divb` by site is unverified: there `site` is a bare integer (`"170"`), here it is `"ID:170"`.
- Week: `week_end` is **text** `YYYY-MM-DD` (Saturday). Compare it as a string: `week_end='2026-09-26'`.
- Pathogen: `pathogen_target` is `"SARS-CoV-2"`, `"Influenza A virus"` or `"RSV"`. Filter on `"Influenza A virus"` for flu.
- Value: `site_wval` (number as a string). The full-dataset max is `2663522980784095400000`, so absurd outliers exist and values must be validated or clamped. The most common value is exactly `1.0` (200960 rows). For CA in the latest week, min is 1.0 and max is 22.53.
- Level label: `site_wval_category`. The full-dataset vocabulary, from `$group`, is exactly `"Very Low"`, `"Low"`, `"Moderate"`, `"High"`, `"Very High"`. The 'limited/no data' category in the description does **not** appear in the data. CA latest week: Very Low 73, Moderate 32, Low 26, High 15, Very High 10.
- Source/provider: `source`. Combos are joined with a comma and space. Full-dataset values are `State_Territory`, `WastewaterSCAN`, `CDC_Verily`, `CDC_Biobot` and combos such as `"State_Territory, WastewaterSCAN"` and `"CDC_Verily, State_Territory, WastewaterSCAN"` (11 distinct values). The casing is `CDC_Verily`, not `CDC_VERILY`, and no `NWSS` value exists. **WastewaterSCAN is present.** CA latest week: `WastewaterSCAN` 81, `State_Territory` 63, `"State_Territory, WastewaterSCAN"` 12.
- Method/version: there is no method column. `date_updated` is the processing-run stamp (text `"2026-10-02 11:03"`). `date_included_in_wval` is the date the site joined the WVAL calculation.

**Notes for the normalizer**

- Geography: `state_territory` holds **lower-case** postal codes (`"ca"`). There are 52 distinct values, including `dc`, `gu` and `vi`; there is no `nd` or `pr`. The sampling site is `site`, a bare integer string (`"170"`); compare `"ID:170"` in `atcp-73re`.
- County FIPS: `county_fips` holds 5-digit, zero-padded strings, as a **comma-and-space list for multi-county sites** (`"06075, 06081"`; 12 of the first 60 CA rows). `counties_served` lists the names, but **not in the same order** as the FIPS: `"06075, 06081"` comes with `"San Mateo, San Francisco"`, while 06075 is San Francisco. Do not zip the two lists by position.
- Week: there is **no week column**. Samples are dated by `sample_collect_date` (text `YYYY-MM-DD`, daily), so derive the MMWR week yourself.
- Pathogen: `pcr_target` is always `"fluav"` (the dataset is Influenza A only). `pcr_gene_target_agg` is `"infa1"` for State_Territory rows and `"infa1 and infa2 combined"` for WastewaterSCAN rows.
- Value: `pcr_target_avg_conc` / `pcr_target_avg_conc_lin`. **The units depend on the source**: `pcr_target_units` is `"copies/l wastewater"` for State_Territory and `"copies/g dry sludge"` for WastewaterSCAN. `pcr_target_mic_lin` is PMMoV-normalized. `pcr_target_flowpop_lin` is mostly absent (3 of the first 60 rows). `pcr_target_detect` is `"yes"`/`"no"`, and `lod_sewage` is the detection limit. Per the metadata, concentrations should not be compared across sites.
- Level label: none.
- Source/provider: `source`. Full-dataset `$select=source,count(*)&$group=source` returned exactly `"State_Territory"` (198637), `"WastewaterSCAN"` (95000) and `"CDC_Verily"` (38271). There are no combo values and no `CDC_Biobot`, unlike `atcp-73re`. WastewaterSCAN data is CC BY-NC 4.0 per the metadata.
- Method/version: `major_lab_method` (`"1"`), `pcr_type` (`"ddpcr"`), `concentration_method`, `extraction_method`, `sample_type`, `sample_matrix`, `sample_location`, and `date_updated` (`calendar_date` processing stamp).
